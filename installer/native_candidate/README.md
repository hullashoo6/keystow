# Native candidate evidence, NOT FOR RELEASE

This branch changes only the NumPy-input guard/dependency staging and candidate engineering tools. It is not a release or sale-cleared installer. No released app version, website, existing publisher or verifier workflow changes belong here.

The dispatch-only candidate workflow uses standard Windows/macOS runners. It verifies exact branch and commit identity before installing dependencies, stages a hash-verified faster-whisper1.2.1 wheel with only the av>=11 metadata dependency removed, and preserves all other upstream constraints and metadata. The source adaptation changes eager PyAV import to lazy import in unsupported file-decoding functions. Application input is restricted to finite mono float32 NumPy waveforms. Reviewed source hashes are pinned in application code; adjacent JSON is not the trust root. Frozen loader code must equal compilation of the hash-verified source. This is an integrity guard, not protection against replacing the whole executable.

Proof distinguishes14pristine source/metadata checks from74adapted-runtime regressions and4narrow Qt filter tests. Real installed/frozen inference uses the public OpenAI Whisper JFK fixture, with source/converted hashes recorded, and an exact existing base-model revision and four file hashes. No user microphone data is included. Runtime hook diagnostics require explicit candidate flags and are built into the actual application entrypoint, not a substitute executable.

Each target records actual PE or Mach-O native-object architecture and dependencies, complete regular-file/symlink hashes, and actual frozen PYZ inventory. Any PyAV/FFmpeg/QtVirtualKeyboard entry or native dependency fails the target. The narrow Qt hook filters only the unused VirtualKeyboard platform-input plugin before dependency scanning. It does not delete all Qt input or platform support.

Fresh-profile Ready smoke uses an explicit dummy keyboard backend and Qt offscreen rendering. The pixels come from the actual loaded UI and bundled base model. It does not prove real microphone access, OS-wide hold/release, focused paste/clipboard, tray or login behavior. No installed-device, platform signing, redistribution/license or release clearance follows.

Windows output is an inspectable onedir ZIP. macOS output is an inspectable native onedir tar.gz preserving symlinks, not a signed .app, universal binary or notarized installer. Only the native architecture of the actual selected runner is covered. RNNoise Windows DLL comes from the target pyrnnoise wheel; macOS keeps existing unavailable-library passthrough and is not native-denoise acceptance.

Candidate archives are measured before upload and capped220MiB per target. Safe diagnostic evidence is fixed-allowlist and capped10MiB per target. Total run upload is bounded460MiB and retained one day. Over-cap outputs are not uploaded; failure evidence remains bounded. No caches, paid services, release/tag/package/deploy steps, secrets or repository write token are used in this workflow. The account's $0 stop-usage budget is the separate no-spend backstop. A rejection or quota block is a blocker, never permission to raise limits.
